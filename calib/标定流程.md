# Seeker1 四路鱼眼标定与全景流程

## 0. 这套标定到底在标什么

四路相机是一套刚性装配的环视模组，标定分两部分：

1. **每路相机的内参 + 畸变（4 组）**
   - 内参：`fx, fy, cx, cy`，omni 模型再加 `xi`
   - 畸变：`k1, k2, p1, p2`（radtan）；另外输出一套 `k1..k4`（equidistant）用于核对
   - 四路镜头是四个独立镜头，必须分别标定，不能共用一组内参
   - 内参与当前分辨率绑定，本流程按实际的 1920x1200 标定

2. **相邻相机的外参（3 组）**
   - `left -> right`、`right -> bright`、`bright -> bleft`
   - 每组是一个 4x4 变换 `T_cn_cnm1`，包含旋转 R 和平移 t
   - 平移 t 的模长就是这两路相机的“基线长度”，所以不需要单独的“基线标定”，它本来就包含在外参里
   - 当前采用链式结构：cam0 的 `T_cn_cnm1` 为单位阵，cam1/cam2/cam3 分别相对上一路
   - 第 4 条 `bleft -> left` 不参与求解；三组链式外参已经确定四路位姿。若以后拼接接缝有明显错位，可以再补拍这一对做闭环校验

3. **本流程不标定的内容**
   - `T_cam_imu`：相机到 IMU 的外参，YAML 中写单位阵
   - `timeshift_cam_imu`：相机与 IMU 时间偏移，YAML 中写 0
   - 这两项只有做 VIO、深度图或点云融合时才需要；只做全景显示不需要

标定算法概要：

- 用 ChArUco 板在每个镜头里检测角点，并按覆盖范围去重筛选
- 每路分别用 `cv2.fisheye.calibrate`（equidistant）和 `cv::omnidir::calibrate`（omni）求内参
- 对每一组四路同步图，若相邻两路都看到板，就分别求板在各自相机下的位姿，得到相对外参
- 多视角鲁棒平均后用 LM 精化，并计算重投影 RMS
- 输出 `kalibr_cam_chain.yaml`（omni + radtan，给全景节点）和 `kalibr_cam_chain_fisheye.yaml`（pinhole + equidistant，用于核对）

## 1. 每次开机后的准备

1. 给板子接 12V 电源，等 10 秒以上，再插 USB。
2. 启动 Docker Desktop，等它完全起来。
3. 打开 Windows PowerShell，启动主机 adb server（当前 RK3588S-4P 环境推荐）：

```powershell
cd F:\Code\Seeker1
.\docker\start-adb-host.cmd
```

说明：当前 Docker Desktop 的 `docker-desktop` WSL 发行版附加 USB 会失败（usbipd 5.3 需要该发行版里有 bash，而它没有）。所以不要把设备附加到 WSL，让 USB 留在 Windows 主机上，由主机 adb 直接访问；容器里的 `adb` 已配置为通过 `host.docker.internal:5037` 使用同一个 adb server。

如果 `docker exec seeker1 adb devices` 报 adb 版本不匹配或 `adb.real: unknown command`，在容器里重装一次代理：

```powershell
docker cp F:\Code\Seeker1\calib\scripts\install_adb_proxy.py seeker1:/tmp/
docker exec seeker1 python3 /tmp/install_adb_proxy.py
```

4. 确认容器和设备：

```powershell
docker exec seeker1 adb devices
```

应看到类似：

```text

```

5. 确认板端 ROS 在跑：

```powershell
docker exec seeker1 adb shell 'bash -lc "source /opt/ros/noetic/setup.bash; rostopic list | grep fisheye"'
```

正常情况下板端会自动启动四路相机和 IMU。若没有任何 `fisheye` 话题，进入板端 shell 手动启动：

## 3. 摆放与拍摄要求

- 相机模组固定不动（三脚架或放在桌上），只移动标定板。
- 先移开 `left` 镜头前的灰色物体，确保四路都能看到开阔空间。
- 标定板距离：A3 约 0.5–1.5 m；A2 约 0.8–2.0 m。
- 光照均匀，避免板面反光和过曝。
- 每个镜头都要覆盖：画面中心、上下左右四边、四角；每个位置做 ±20°~40° 的俯仰/偏航倾斜。
- 在每个位置停 0.5–1 秒再移动，避免拖影；采集脚本大约每 0.6 秒才允许存一帧。
- 相邻镜头必须同时拍到标定板：
  - `left <-> right`
  - `right <-> bright`
  - `bright <-> bleft`

推荐分两轮：

- 第一轮：依次对着四个镜头各拍 30 个有效视角，覆盖中心和四角
- 第二轮：把板子放到相邻镜头的重叠区，每对拍 12 个同步视角

- `kalibr_cam_chain_fisheye.yaml`：pinhole + equidistant，用于核对单路鱼眼内参


### 哪些数值会明显变化

以 `kalibr_cam_chain.yaml` 为例：

```yaml
cam0:
  camera_model: omni
  distortion_model: radtan
  intrinsics: [fx, fy, cx, cy]          # 每路不同，通常几百像素量级
  distortion_coeffs: [xi, k1, k2, p1, p2]  # xi 通常 0.5-1.5，k/p 为小数
  resolution: [1920, 1200]              # 固定不变
  T_cn_cnm1: 单位阵                       # cam0 固定
  T_cam_imu: 单位阵                       # 本流程不标，固定
  timeshift_cam_imu: 0.0                 # 本流程不标，固定
cam1:
  intrinsics: [...]                      # 与 cam0 明显不同
  distortion_coeffs: [...]               # 与 cam0 明显不同
  T_cn_cnm1: [4x4 旋转+平移]              # 每台机器不同
cam2: ...
cam3: ...
```

重点看：

- `intrinsics`：四路各自的 `fx, fy, cx, cy`，四组数值不应该完全相同
- `distortion_coeffs`：omni YAML 是 `[xi, k1, k2, p1, p2]`；fisheye YAML 是 `[k1, k2, k3, k4]`
- `T_cn_cnm1`：cam1/cam2/cam3 的 4x4 矩阵，旋转和平移都会变
- `T_cam_imu`、`timeshift_cam_imu`、cam0 的 `T_cn_cnm1`：不会变

`calibration_report.json` 里最适合快速检查的是：

- `cameras.<cam>.omni.median_reproj_px`：单路重投影误差
- `cameras.<cam>.omni.xi` / `K` / `D`：omni 内参和畸变
- `cameras.<cam>.used`：实际参与标定的视角数
- `pairs.<a>-<b>.rms`：相邻外参重投影 RMS
- `pairs.<a>-<b>.translation_norm_m`：基线长度（米）
- `pairs.<a>-<b>.rotation_deg`：两路光轴夹角
- `pairs.<a>-<b>.T_cn_cnm1`：完整外参矩阵

## 10. 自动保存的判定逻辑

辅助采集不是“按时间无脑存”，而是按下面顺序判断：

1. 订阅四路 `/fisheye/<cam>/image_raw/compressed`，用 `ApproximateTimeSynchronizer` 做同步，默认 slop 0.04 秒。
2. 处理节流：默认最多 4 组/秒（`--process-hz 4`），超出的帧直接丢弃。
3. 同步检查：四路时间戳最大差必须 <= slop，否则跳过。
4. 解码并降采样到一半分辨率，检测 ChArUco；默认至少检测到 4 个 marker。
5. 取四路中角点数最多的一路作为 `best`：
   - `best` 角点数必须 >= `--min-corners`（默认 10）
   - 距离上次保存必须 >= `--min-save-period`（默认 0.6 秒）
   - 位姿必须相对上次保存发生变化：
     - 角点质心位移 > `--min-shift`（默认 0.025，即画面宽度的 2.5%）
     - 或角点扩散半径变化 > `--min-spread`（默认 10%）
6. 满足以上全部条件才保存：四路各写一张原始 JPEG，序号相同、时间戳相同，并在 `sessions.jsonl` 追加一条记录。
7. 计数规则：
   - 某路角点数 >= `min-corners`，该路有效视角 +1
   - 相邻两路都 >= `min-corners`，该对同步视角 +1
8. 停止条件：四路都达到 `--target-cam`（默认 30）且三对都达到 `--target-pair`（默认 12）；或出现 `/data/local/tmp/stop_capture`；或达到 `--max-seconds`（默认 0，表示不限时）。

注意：采集日志里的角点数是半分辨率检测结果，预览页面里的角点数是全分辨率检测结果，两者可能略有差异；保存判定以采集日志为准。
